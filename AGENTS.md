# AGENTS.md

## Область действия

Правила действуют для всего репозитория `n8n Entrepreneur Starter Kit`.

## Источник истины

- Projects Control (`projects-control-work`) — источник истины для эпиков, задач, зависимостей, leases, документов, evidence и review.
- `docs/product-brief.md` и `docs/architecture.md` — канонические продуктовые и архитектурные документы.
- ADR фиксируют решения. Изменение принятого решения требует нового ADR или явного supersede существующего.

## Обязательный lifecycle

1. Найти dependency-ready задачу в Projects Control.
2. Запустить идентифицированный agent run.
3. Прочитать `task_context`, зависимости и связанные документы.
4. Выполнить `document_check`; stale или missing документы нельзя использовать как основание работы.
5. Взять задачу через `task_claim` до изменения файлов.
6. Работать только в scope задачи; для долгой работы продлевать lease.
7. Запустить проверки, зарегистрировать изменённые документы, добавить evidence.
8. Отправить задачу на review. Реализатор не одобряет собственную работу.
9. Независимый reviewer проверяет evidence и реальные изменения и выносит решение.

## Approval gate

Владелец одобрил backlog 2026-07-13. Foundation-only gate снят, но dependency и architecture gates Projects Control остаются обязательными: runtime implementation нельзя начинать до завершения `T-0002`, `T-0003` и `T-0004`.

До завершения `T-0004` запрещено:

- создавать Docker Compose stack и runtime-конфигурацию;
- реализовывать любые shell-скрипты;
- создавать workflow JSON и fixtures;
- подключать или вызывать внешние credentials;
- запускать продуктовые контейнеры, VPS или deployment;
- создавать CI/CD продуктовой реализации.

## Инженерные правила после снятия gate

- Поддерживать только Ubuntu 24.04 LTS x86_64, пока отдельная задача не расширит матрицу.
- Использовать официальный n8n image и явно закреплённые версии; тег `latest` запрещён.
- Не хранить секреты, credentials, access tokens и реальные персональные данные в Git, workflow JSON, fixtures или logs.
- `.env` создаётся локально с правами `0600`; постоянный `N8N_ENCRYPTION_KEY` обязателен.
- PostgreSQL не публикуется наружу; Docker socket не монтируется в n8n; лишние privileges запрещены.
- Опасные бизнес-действия по умолчанию требуют human approval; draft-only включён по умолчанию там, где применимо.
- Скрипты должны иметь `--help`, безопасную обработку ошибок, понятные русские сообщения и не выводить секреты.
- Фактические проверки отделяются от предположений. Нельзя заявлять об успешном VPS, backup/restore, HTTPS или provider test без evidence.
- Документация для пользователя пишется по-русски, простыми действиями, с командами для копирования и ожидаемым результатом.

## Definition of Done задачи

Задача завершена только когда выполнены её acceptance criteria, обновлён documentation outcome, пройдены релевантные проверки, evidence привязан в Projects Control и независимое review одобрило результат.
