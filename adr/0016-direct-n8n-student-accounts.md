# ADR-0016: Прямой вход ученика в n8n по собственному аккаунту

Дата: 2026-08-05
Статус: accepted
Supersedes: ADR-0013 полностью; ADR-0015 в части gateway, ticket и revocable cookie

## Контекст

ADR-0015 и ADR-0013 закрывали доступ ученика к n8n одноразовым ticket и Caddy
`forward_auth`: ученик никогда не получал прямой адрес инструмента и заходил
только по кнопке из своего пространства.

Владелец пересмотрел продуктовую модель 2026-08-05. Ученику выдаётся обычный
аккаунт в n8n, он входит по собственным учётным данным и работает в своём
пространстве. Промежуточный запуск через платформу перестаёт быть частью
пользовательского пути.

Отдельным фактом: 2026-08-05 Chrome показывает на `n8n.neurokurs.ru`
предупреждение Safe Browsing «Опасный сайт». На момент решения хост отдаёт
неавторизованному пустой `401`, то есть обманного содержимого не публикует.
Точная причина флага не установлена и подлежит выяснению в Google Search
Console.

## Решение

1. Ученик получает **приглашение n8n**. Платформа находит или приглашает
   Member через официальный Public API по точному email; ученик сам задаёт
   пароль. Платформа не хранит, не показывает и не передаёт пароль.
2. Убираются ticket, gateway cookie, привязка сессии к поколению назначения,
   маршруты `/api/tool-gateway/**` и оба `launch`, а также `forward_auth` и
   `/__neurokurs/exchange` в managed Caddy profile.
3. **Сохраняется** канал управления: матчер `/api/v1/*` в Caddy с заголовком
   `X-Neurokurs-Management` и derived secret из `AUTH_SECRET`. Без него
   платформа не может создавать приглашения, то есть отменять его нельзя.

   Важно не переоценивать оставшуюся защиту: после снятия `forward_auth` этот
   матчер **больше ничего не ограничивает**. Запрос на `/api/v1/*` без
   заголовка просто не совпадает с ним, проваливается в общий `handle` и всё
   равно доходит до n8n. Матчер теперь снимает служебный заголовок перед
   проксированием, а доступ к Public API защищает сам n8n через
   `X-N8N-API-KEY`.
4. Сохраняются учёт назначений в `tool_access`, срок доступа и обязательный
   license mode: они остаются продуктовым и лицензионным контролем.
5. Публичные endpoint n8n (`/healthz`, `/webhook/*`, `/form/*`) остаются
   доступны, редактор становится доступен по обычному логину.

## Последствия

- **Отзыв доступа перестаёт быть мгновенным.** Раньше отзыв закрывал gateway
  на следующем запросе. Теперь отзыв в платформе — это отметка в `tool_access`;
  фактический доступ прекращается только отключением или удалением аккаунта в
  n8n. Это ослабление, принятое сознательно.
- **Адрес инструмента становится публично известным.** Форма входа n8n будет
  доступна всем. Это увеличивает поверхность атаки и, вероятно, тот самый
  класс содержимого, который вызывает эвристику Safe Browsing. Снятие флага
  через Search Console становится обязательным условием запуска, а не
  желательным улучшением.
- Ученик может задать слабый пароль; политика паролей теперь принадлежит n8n,
  а не платформе.
- Упрощается модель: исчезает целый слой ticket/cookie/поколений и связанные
  с ним тесты и таблицы.
- Таблицы `tool_gateway_tickets` и колонки поколения перестают использоваться.
  Их удаление выполняется отдельной миграцией после того, как код перестанет
  на них ссылаться.

## Источники

- Официальный n8n Public API `GET /api/v1/users/:email` и `POST /api/v1/users`
  для поиска и приглашения Member, проверено при работе над ADR-0013.
- [Google Search Console: меры, принятые вручную и проблемы безопасности](https://support.google.com/webmasters/answer/9044101)
  — порядок запроса проверки после устранения причины.
