# Product brief

## Продукт

**Название:** n8n Entrepreneur Starter Kit.

**Формат:** открываемый пользователем комплект конфигурации, Bash-скриптов, импортируемых workflow, тестов и русскоязычной документации для официального self-hosted n8n Community Edition.

## Проблема

Участник ИИ-интенсива умеет собирать workflow в визуальном редакторе, но после обучения не должен зависеть от преподавателя при развёртывании и эксплуатации собственного n8n. Типичная инструкция требует знания Linux, DNS, Docker, TLS, backup и диагностики. Ошибка в любом звене превращает обучение в поддержку инфраструктуры.

## Целевая аудитория

Предприниматель или сотрудник малого бизнеса:

- не имеет системного DevOps-опыта;
- способен арендовать VPS, купить или использовать домен и выполнить команды по инструкции;
- разворачивает один экземпляр для внутренних задач своей организации;
- самостоятельно получает credentials внешних Telegram, email, CRM и LLM сервисов.

Преподаватель — вторичный пользователь: ему нужен воспроизводимый стенд, диагностический сценарий и инструкция передачи системы участнику.

## Job to be done

«Когда интенсив закончен, я хочу за один сеанс развернуть собственный защищённый n8n на VPS и убедиться диагностикой, что он работает, чтобы продолжить автоматизацию без доступа к инфраструктуре преподавателя».

## Целевой путь

1. Арендовать VPS и направить A-запись домена на его IPv4.
2. Подключиться по SSH и загрузить версионированный release или клонировать репозиторий.
3. Запустить локальный `install.sh`.
4. Ответить на понятные вопросы или передать config/env в неинтерактивном режиме.
5. Получить n8n, PostgreSQL и HTTPS, пройти автоматическую диагностику.
6. Открыть n8n, создать owner account и добавить credentials.
7. Импортировать стартовые workflow и выполнить LLM/Telegram diagnostics.
8. Получить команды backup, restore, update, rollback и doctor.

## Главная метрика

Новый пользователь без DevOps-опыта проходит документированный путь от чистой поддерживаемой Ubuntu 24.04 до доступного по HTTPS n8n за 15–30 минут без устных пояснений.

Метрика подтверждается наблюдаемым usability trial; скорость опытного разработчика или симулированный результат не считаются подтверждением.

## MVP outcome

На чистой Ubuntu 24.04 LTS x86_64:

- stack устанавливается повторяемо и переживает reboot;
- n8n доступен по валидному HTTPS;
- PostgreSQL healthy и не доступен из интернета;
- doctor выдаёт понятный отчёт;
- backup → удаление тестовых данных → restore фактически подтверждает восстановление;
- update и rollback проверены между заранее выбранными совместимыми версиями;
- generic LLM test и Telegram test проходят после ввода пользователем credentials;
- четыре демонстрационных workflow импортируются без секретов;
- Quick Start, Timeweb Cloud и Yandex Cloud инструкции проходимы;
- лицензирование и ограничения использования объяснены без представления текста как юридического заключения.

## В scope MVP

- Ubuntu 24.04 LTS x86_64, sudo, публичный IPv4 и домен/поддомен;
- Docker Engine и Docker Compose plugin;
- n8n Community Edition, PostgreSQL, Caddy, volumes и health checks;
- install, doctor, backup, restore, update, rollback, uninstall, import/export workflows;
- generic OpenAI-compatible LLM path, Yandex AI Studio и GigaChat после отдельной проверки официальных API;
- reusable sub-workflows и четыре демонстрационных бизнес-сценария;
- автоматические статические, integration и end-to-end проверки;
- русскоязычная документация для участника и преподавателя.

## Не входит в MVP

- собственный публичный SaaS, перепродажа n8n, white label или модифицированный коммерческий image;
- поддержка всех Linux-дистрибутивов и архитектур;
- multi-node high availability, Kubernetes, Redis/queue mode и enterprise SSO;
- локальные LLM, Ollama и vector databases;
- автоматическая покупка VPS, домена или credentials;
- хранение пользовательских secrets в репозитории;
- LiteLLM в базовом профиле;
- обещание полной совместимости любого OpenAI-like provider без тестов.

## Риски продукта

- UI и API внешних провайдеров меняются; инструкции должны содержать дату проверки и ссылаться на официальные источники.
- Минимальная машина 1 vCPU/1 GB пригодна только для теста; реальное использование может потребовать больше ресурсов.
- Workflow execution data может содержать персональные данные и требует pruning и осознанной политики хранения.
- Автоматизация исходящих сообщений и CRM-изменений создаёт бизнес-риск; human approval обязателен по умолчанию.
- Sustainable Use License и provider terms требуют проверки на дату релиза.

## Product gates

1. **Backlog approval:** никакой реализации до одобрения владельцем.
2. **Architecture evidence:** версии, API и лицензия подтверждены официальными источниками и ADR.
3. **Local/disposable verification:** статические и integration проверки пройдены.
4. **Real Ubuntu verification:** заявленные install/reboot/HTTPS/backup/update проверки имеют evidence.
5. **Usability verification:** новый пользователь проходит Quick Start без устных подсказок.
