# Product brief

## Продукт

**Название:** n8n Entrepreneur Starter Kit.

**Формат:** открываемый пользователем комплект конфигурации, Bash-скриптов, импортируемых workflow, тестов и русскоязычной документации для официального self-hosted n8n Community Edition.

## Multi-product граница репозитория

С 2026-07-29 в этом же репозитории проектируется второй продукт — Course Control Plane в изолированном каталоге `platform/`. Он не изменяет описанный ниже MVP starter kit: root Compose, installer, scripts и workflow distribution остаются самостоятельно устанавливаемым продуктом.

Control plane размещается в одном Vercel project с deployable root `platform/`. Его пользовательский продукт — **Neurokurs**, закрытое рабочее пространство курса: единая точка доверия для текстовых материалов, заданий, помощи и учебных инструментов. Продажа курса происходит вне Neurokurs; публичный вход только объясняет назначение пространства и не является маркетинговой воронкой или полноценной LMS.

Для владельца курса тот же deployable предоставляет отдельную административную область: управление учениками, контентом, учебными инструментами и поддерживающей их облачной инфраструктурой. Первый infrastructure adapter автоматизирует один основной Timeweb VPS, DNS в зоне `neurokurs.ru`, установку exact starter-kit release и удаление ресурсов. Provider и VPS — детали реализации учебного инструмента, а не сущности первого уровня в интерфейсе ученика. Требования зафиксированы в [course platform requirements](course-platform-requirements.md), repository/runtime boundaries — в [ADR-0005](../adr/0005-course-platform-control-plane.md), а упрощение deployment — в [ADR-0006](../adr/0006-single-vercel-project-for-course-platform.md).

Следовательно, пункты ниже «собственный публичный SaaS» и «автоматическая покупка VPS» остаются вне **starter-kit MVP**, но больше не запрещают отдельную platform-реализацию в `platform/`. Platform имеет собственные auth/RBAC, Vercel deployment, secrets, CI, release gates и лицензионную проверку n8n.

## Проблема

Участник ИИ-интенсива до курса мог пользоваться только чатом с ИИ и впервые открывает n8n. После обучения он не должен зависеть от преподавателя при запуске готовых сценариев и эксплуатации собственного n8n. Типичная инструкция требует знания визуальных workflow, Linux, DNS, Docker, TLS, backup и диагностики. Ошибка в любом звене превращает обучение в поддержку инфраструктуры.

## Целевая аудитория

Предприниматель или сотрудник малого бизнеса:

- не имеет системного DevOps-опыта;
- не имеет опыта программирования и может впервые видеть визуальный редактор автоматизаций;
- способен арендовать VPS, войти в него по SSH или через web-console и вставить одну команду;
- не обязан заранее владеть доменом или понимать DNS;
- разворачивает один экземпляр для внутренних задач своей организации;
- самостоятельно получает credentials внешних Telegram, email, CRM и LLM сервисов.

Преподаватель — вторичный пользователь: ему нужен воспроизводимый стенд, диагностический сценарий и инструкция передачи системы участнику.

## Job to be done

«Когда интенсив закончен, я хочу за один сеанс развернуть собственный защищённый n8n на VPS и убедиться диагностикой, что он работает, чтобы продолжить автоматизацию без доступа к инфраструктуре преподавателя».

## Целевой путь

1. Арендовать VPS с Ubuntu 24.04 x86_64 и публичным IPv4.
2. Подключиться по SSH или открыть web-console провайдера.
3. Вставить одну опубликованную команду `curl -fsSL <stable HTTPS URL>/install.sh | sh`.
4. Получить автоматически сформированный бесплатный hostname, n8n, PostgreSQL и валидный HTTPS.
5. Открыть напечатанный URL, создать owner account и добавить credentials.
6. Импортировать стартовые workflow и выполнить LLM/Telegram diagnostics.
7. При желании подключить собственный домен как отдельное advanced-действие.
8. Получить команды backup, restore, update, rollback и doctor.

## Главная метрика

Новый пользователь без DevOps-опыта проходит документированный путь от чистой поддерживаемой Ubuntu 24.04 до доступного по HTTPS n8n за 15–30 минут без устных пояснений.

Метрика подтверждается наблюдаемым usability trial; скорость опытного разработчика или симулированный результат не считаются подтверждением.

## MVP outcome

На чистой Ubuntu 24.04 LTS x86_64:

- stack устанавливается повторяемо и переживает reboot;
- n8n доступен по валидному HTTPS;
- PostgreSQL healthy и не доступен из интернета;
- doctor выдаёт понятный отчёт;
- backup → удаление тестовых данных → restore фактически подтверждает восстановление;
- update и rollback проверены между заранее выбранными совместимыми версиями;
- generic LLM test и Telegram test проходят после ввода пользователем credentials;
- десять демонстрационных no-code workflow импортируются без секретов;
- Quick Start, Timeweb Cloud и Yandex Cloud инструкции проходимы;
- лицензирование и ограничения использования объяснены без представления текста как юридического заключения.

## В scope MVP

- Ubuntu 24.04 LTS x86_64, sudo и публичный IPv4;
- автоматический стартовый hostname через IP-derived DNS и необязательный собственный домен;
- Docker Engine и Docker Compose plugin;
- n8n Community Edition, PostgreSQL, Caddy, volumes и health checks;
- install, doctor, backup, restore, update, rollback, uninstall, import/export workflows;
- generic OpenAI-compatible LLM path, Yandex AI Studio и GigaChat после отдельной проверки официальных API;
- десять самостоятельных демонстрационных бизнес-сценариев без Code/Function/Execute Workflow nodes в beginner distribution;
- reusable advanced sub-workflows в репозитории, но не в beginner runtime;
- автоматические статические, integration и end-to-end проверки;
- русскоязычная документация для участника и преподавателя.

## Не входит в MVP

- собственный публичный SaaS, перепродажа n8n, white label или модифицированный коммерческий image;
- поддержка всех Linux-дистрибутивов и архитектур;
- multi-node high availability, Kubernetes, Redis/queue mode и enterprise SSO;
- локальные LLM, Ollama и vector databases;
- автоматическая покупка VPS, собственного домена или credentials;
- хранение пользовательских secrets в репозитории;
- LiteLLM в базовом профиле;
- обещание полной совместимости любого OpenAI-like provider без тестов.

## Риски продукта

- UI и API внешних провайдеров меняются; инструкции должны содержать дату проверки и ссылаться на официальные источники.
- Минимальная машина 1 vCPU/1 GB пригодна только для теста; реальное использование может потребовать больше ресурсов.
- Workflow execution data может содержать персональные данные и требует pruning и осознанной политики хранения.
- Автоматизация исходящих сообщений и CRM-изменений создаёт бизнес-риск; human approval обязателен по умолчанию.
- Sustainable Use License и provider terms требуют проверки на дату релиза.
- Стартовый hostname зависит от внешнего IP-derived DNS; installer обязан fail-closed проверять соответствие hostname публичному IPv4 и объяснять fallback на собственный домен.
- Публичная one-command установка невозможна без выбранной лицензии и стабильного HTTPS distribution URL.

## Product gates

1. **Backlog approval:** никакой реализации до одобрения владельцем.
2. **Architecture evidence:** версии, API и лицензия подтверждены официальными источниками и ADR.
3. **Local/disposable verification:** статические и integration проверки пройдены.
4. **Real Ubuntu verification:** заявленные install/reboot/HTTPS/backup/update проверки имеют evidence.
5. **Usability verification:** новый пользователь проходит Quick Start без устных подсказок.
